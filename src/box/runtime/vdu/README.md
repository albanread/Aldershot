# The VDU drivers

RISC OS's VDU drivers, reimplemented in native C from the kernel's sources (`Kernel/s/vdu`), pixel for pixel. They own what is on the screen. DRMVideo (`modules/drmvideo`) owns the hardware beneath them, and they reach it through GraphicsV, as the kernel's drivers do.

WrchV's default owner (`runtime/streams.c`) gives every character to `ros_vdu_write`, or to VDUXV while OS_Byte 3 (or 236) has bit 5 set. The serial console gets a copy of the text only. Unknown VDU 23 codes go to UKVDU23V, and PLOT codes &D0 and up (except &E8 to &EF, sprites) go to UKPLOTV. The Font Manager claims both.

| `vdu5.c` | VDU 5 characters at the graphics cursor |
| `sprite.c`, `sprplot.c`, `sprout.c` | `OS_SpriteOp` through SpriteV, sprite plotting and screen save and load, and output to a sprite or mask |
| `pointer.c` | the pointer and mouse: `OS_Word` 21, `OS_Byte` 106, `OS_Mouse`, `OS_Pointer`, PointerV |

`OS_ChangedBox` is kept as the kernel keeps it. While it is on, everything the drivers draw is added to the box. The five words live in the RMA, as Draw, the Font Manager and the Wimp write the box themselves.

## Virtual displays

A task can have a screen of its own, a virtual display in a mode of its own. The VDU draws into it while the task's code runs. GraphTask shows one in a desktop window, and the native Wimp draws it (`modules/wimp/surface.c`).

- The VDU's state (`struct vdu`, the RMA blocks it hands out, the save area, teletext's state) is a context. The real display has one and each virtual display has another. `vdu.vd` names the live one (NULL for the real one).
- The running task's display is live while its own code runs. The real display is live for background work and for every Wimp SWI.
- A mode change in a virtual display has no ScreenModes check and no GraphicsV. The palette, blanking and teletext bank flips stay in the context. The mouse is mapped into the display's rectangle, with buttons only when it has the input focus.
- The screen is a dynamic area "VDisplay n" of two banks, each a sprite area holding one sprite, `screen`.
- The SWIs (`api/defs/vdisplay.toml`, chunk &C01C0) are `VDisplay_Create`, `Destroy`, `Attach`, `Info`, `SetFocus`, `Changed` and `SetMode` (&C01C6). A task's end detaches its display. TaskWindow's `-vdisplay <handle>` gives a task window's child one (`modules/taskwindow/README.md`).

`boot/selftest_vdisplay.c` tests it.

## Differences from RISC OS 5.30

- MODE 7 is what 5.30 makes it on the Pi. No monitor lists mode 7's 640 by 500, so it becomes an 800 by 600 mode selector at 8 bpp, 255 colours, 40 by 25 characters, with the page centred. `modes.c` makes the same selector, because there is no ScreenModes. `OS_CheckModeValid 7` says "not valid, with this substitute". A mode selector is accepted only in a pixel format the driver lists.
- The teletext hard scroll never happens. Scrolls go through the soft scroll. 5.30 hard-scrolls a borderless 8 bpp page, which hangs the farm machine.
- DRMVideo lists 1, 2 and 4 bpp and 32 bpp `&xRGB`, which the farm's Pi does not. Neither lists alpha formats.
- Teletext screen memory is two banks. The flash phases are the kernel's 48 and 16 VSyncs, moved by GraphicsV `SetDMAAddress`.
- A few kernel quirks are copied literally: SetColours spreads a text colour with bits above the pixel's into the lower lanes of the word, and spreads it again each time it runs. VDU 23,2 to 5 at 16 and 32 bpp in BBC mode reads the bytes after its table in the ROM. VDU 23,12 to 15 at 1 bpp reads its colours from address 0.

Not done:

- VDU 4 cursor directions other than left to right, top to bottom, and CursorFlags bit 4's wrap instead of scrolling. VDU 23,7 and 23,8 honour the directions, but the cursor's own movement does not.

## Tests

`tests/vdu/compare.py` plays VDU byte streams (`tests/vdu/streams.py`) on RISC OS 5.30 on the farm (through `tests/vdu/Play`, a BASIC program) and on the hosted build (`ROSGD_VDUPLAY`, `boot/vduplay.c`). It compares screen memory byte for byte, the mode and VDU variables, every palette entry, POS and VPOS, and `OS_Byte` 117. A stream may also carry SWI calls whose registers, errors, sprite areas and saved files are compared. All streams are identical except five that wait on the cursor directions.
The streams cover text, windows, scrolling, graphics, sprites, ColourTrans, the mouse, `OS_ChangedBox`, and teletext in modes 7, 28, 32 and the 64K and 16M colour selectors.

- `boot/selftest_vdu.c` checks what the farm cannot: 1, 2 and 4 bpp modes, double-pixel and gap modes, the pointer shapes given to GraphicsV, and the text colour lanes at low depths.
- `tests/vdu/mode7box.py` shows MODE 7 in the headless box and dumps the screen for each flash bank. `tests/vdu/Mode7Demo` is a broadcaster's page.
- `tests/desktop/international` checks the International module's drawing of the font.
